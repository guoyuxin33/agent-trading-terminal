# Agent Desk

A local AI trading terminal with a visible multi-agent workflow, DeepSeek tool calling, Binance's official MCP client, and an auditable spot paper-trading ledger.

一个可以看见 Agent 工作、读懂每次决策、追溯每笔成交的本地 AI 模拟交易终端。

## What works

- Live agent activity through Server-Sent Events: SCOUT → MEMORY → ANALYST → RISK → EXECUTOR → LOGGER.
- Create additional reviewer agents with their own prompts. In real-market mode each reviewer makes a separate DeepSeek request and can veto a proposed trade.
- DeepSeek tool-calling loop with `recall_trades` and `submit_decision`, a three-round budget and response validation.
- Official Binance MCP Streamable HTTP client with OAuth PKCE, state validation, token refresh through the MCP SDK, tool discovery and read-only tool gating.
- Explicit public Binance REST fallback when MCP is disconnected. The UI always identifies the actual data source.
- Spot paper execution with cash/position accounting, fixed adverse slippage, entry/exit fees, stop-loss and take-profit monitoring.
- Per-trade entry/exit fills, fees, decision evidence, model version, risk checks and timestamps.
- A SQLite journal and encrypted local API keys / OAuth tokens; JSON export contains no credentials.
- Isolated synthetic demo and real-market paper accounts. Switching sources never merges their returns.

## Run

Requires **Node.js 24+** and **pnpm 11**.

```sh
pnpm install
pnpm build
pnpm start
```

Open **http://127.0.0.1:8787**. Click **开始模拟** to run the synthetic demonstration. There are twelve explicitly labeled demo replay trades on first launch, generated by the same ledger used by the app; these are not historical market performance.

Development:

```sh
pnpm dev
```

Open http://127.0.0.1:5173. The frontend proxies `/api` to the local backend on port 8787.

```sh
pnpm test
pnpm build
```

## Connect DeepSeek

1. Pause the desk and wait for the current cycle to complete.
2. Open **连接与设置** and enter your own DeepSeek API key and model ID.
3. Save and test. The test reads the models accessible to your key.
4. Choose **Binance 实时行情 · 模拟账户** and save.
5. Start paper trading. Model errors reject that cycle; they never silently switch into the demo strategy.

Keys can alternatively be supplied through the environment (copy `.env.example` to `.env`). Model IDs change; `deepseek-flash` is the initial configurable default. The example uses the official OpenAI-compatible `/chat/completions` API and tool calls.

Only the analyst and extra reviewers call the model. Risk and execution use ordinary deterministic code. A fixed set of BTCUSDT / ETHUSDT / SOLUSDT spot pairs is used in this first release.

## Connect the official Binance MCP

Official documentation: https://developers.binance.com/zh-CN/docs/agent-native/mcp-server/agentic

The application uses **https://agent.binance.com/mcp/agentic**, not a third-party Binance MCP implementation.

1. Open **连接与设置 → Binance MCP Server**.
2. If Binance requires a pre-registered client, supply an OAuth Client ID issued **for this application**. The app can attempt dynamic registration if the authorization server supports it. Do not reuse the `codex` or `grok` identities from Binance's examples.
3. Register the exact callback URI **http://127.0.0.1:8787/api/binance/callback** if required.
4. Click **连接 Binance**, then open the returned authorization link and complete authentication and consent yourself on Binance.
5. Inspect the discovered tools. Select the compatible read-only ticker tool if automatic matching fails, then save.

Binance access may require regional eligibility, a supported account and an approved OAuth client. Registration availability is controlled by Binance. This repository cannot bypass it. The live integration cannot be validated end to end without your credentials and Binance consent.

The client accepts ticker responses containing `lastPrice` or `price`, optionally nested in `data` / `result` / `response`. Tool schemas requiring parameters other than `symbol` / `symbols` need an adapter in `server/adapters.mjs`; the app reports unsupported schemas rather than guessing an executable request.

When disconnected, public market quotes come from `https://data-api.binance.vision/api/v3/ticker/24hr`. The UI shows **Binance Public REST**, so REST data is never presented as a successful MCP connection.

If your network requires a proxy, set `HTTPS_PROXY` and optionally `NO_PROXY=127.0.0.1,localhost` in your local `.env` file. No proxy address or secrets are committed.

## Execution scope

**This release executes paper trades only.** There is no live-order API route or one-click live toggle. Binance order, transfer, conversion and withdrawal tools are not exposed to the model. Binance's current official workflow requires user confirmation for fund-moving operations; connecting MCP does not grant this app unattended live trading.

Initial rules are configurable while paused:

| Rule | Initial value |
| --- | --- |
| Simulated capital | 10,000 USDT |
| Position size | 8% of current equity |
| Concurrent positions | 3 maximum, one per symbol |
| Stop / take profit | 1.5% / 3% from entry |
| Minimum confidence | 70 / 100 |
| Quote freshness | 30 seconds maximum |
| Fees / adverse slippage | 10 bps / 5 bps per side |
| Daily realized loss limit | 3% of initial equity, UTC day |
| Additional equity protection | Block entries below 97% of initial equity |

Pause stops **new entries** and invalidates pending model decisions. Existing simulated positions continue to be monitored. Stop exits fill at the next observed quote including slippage; the stop price is not guaranteed. If the app is stopped or market data is unavailable, it cannot monitor positions.

The paper matcher is an initial fixed-bps model. It does **not** simulate order-book depth, partial fills, exchange symbol filters, websocket latency, funding, margin or liquidation. Positive paper results do not establish live executability. The demo has no predictive strategy. The real-market analyst currently receives a ticker snapshot and past trades; richer candle/order-book features should be added and evaluated before strategy research conclusions are drawn.

Experience is retrieved from completed trades, with source labels. It does not automatically retrain DeepSeek or modify trading rules. Prompt changes and risk settings remain user controlled.

## Local data and security

- Binds to `127.0.0.1` only. Do not expose this initial local application directly to the internet.
- Host/origin checks and an explicit local-operation header protect state-changing routes from ordinary cross-site requests.
- Local credentials are AES-256-GCM encrypted in `data/desk.sqlite`; the local key is `data/secret.key`.
- `data/`, `.env`, `node_modules/` and build output are ignored by Git.
- This protects against accidental plaintext disclosure, not an attacker who controls your OS user and can read both database and encryption key.
- A restart restores the journal and positions but does not automatically restart new entries or restore an active MCP session. Reconnect MCP explicitly.
- Local disconnect clears the saved tokens. Revoke server-side grants through Binance account settings when needed.

## Architecture

```text
React UI ── REST / SSE ── Local Express service
                           ├── Persistent event/state harness
                           ├── DeepSeek bounded tool loop
                           ├── Binance MCP + OAuth PKCE
                           ├── Deterministic risk checks
                           ├── PaperBroker / position monitor
                           └── SQLite journal + local secret store
```

Main files:

- `src/main.tsx`: dashboard, agent workspace, journal, settings and trade detail views.
- `server/desk.mjs`: orchestration, task state, independent reviews and event journal.
- `server/adapters.mjs`: DeepSeek / Binance MCP / public quote adapters.
- `server/ledger.mjs`: risk validation and paper accounting.
- `server/store.mjs`: SQLite persistence and credential encryption.
- `tests/`: accounting, isolation, interruption, model failure and tool-boundary regression tests.
